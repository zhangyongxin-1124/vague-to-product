# 案例库（examples/）

> 用真实样例告诉你：一句模糊的话，经过 vague-to-product 挖掘后能产出什么。
> **性质标注**：案例分两类，绝不混淆——
> - 【真实】来自真实项目的推演与交付记录，只做隐私脱敏，不改动结论；
> - 【演示】按真实需求类型整理的演示性推演，用于展示方法与输出形态，**不是**真实交付记录。

| 案例 | 类型 | 输入一句话 | 最终产出 |
|---|---|---|---|
| [01 闹钟App](01-闹钟App-从一句话到PRD与终局交付.md) | 【真实】 | "我想做一个闹钟 App" | 一页纸 PRD（D3）→ 终局交付约定 → 合规流程报告 |
| [02 娱乐小程序](02-娱乐小程序-逆向施工图摘要.md) | 【真实】 | "我想做一个娱乐小程序" | 19 条合规红线 + 10 个死亡点 + 8 步倒排计划（完整版在 fuzzy-reverse-flow 仓库 examples/） |
| [03 社区奶茶店](03-实体店-社区奶茶店可行性推演.md) | 【演示】 | "我想在小区门口开家奶茶店" | 实物/经营类推演：伪需求体检 + 红线 + 办证清单 |
| [04 商业计划书](04-文档类-商业计划书十页成稿.md) | 【演示】 | "帮我把想法写成一份商业计划书" | 文档类：从方向说明到十页成稿的分批产出 |

## 怎么读案例

1. 先看「输入」与「最终产出」对照——这就是 vague-to-product 与普通 AI 的差别；
2. 再看挖掘过程里的关键追问（为什么问这些、为什么只问这些）；
3. 最后看交付物自带的「你要怎么自己验证」清单——那是你拿到成品后该做的事。

## 复现

```bash
python scripts/v2p.py route -t "<案例里的那句话>"
```
