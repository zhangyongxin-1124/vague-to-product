# MVP 功能分级表

> 判定一句话：**删掉这功能，用户还能拿到他要的结果吗？**
> 不能 → P0 ｜ 能但会抱怨 → P1 ｜ 能不抱怨 → P2 或不做

## 分级

| 级别 | 含义 | 数量上限 | 交付时间 |
|---|---|---|---|
| P0 | 不做就不能用 | ≤5 | 第一轮就做 |
| P1 | 有更好，没有也能忍 | ≤5 | 第二轮 |
| P2 | 以后再说 | 不限 | 不做，只记录下来 |

## 表格

| # | 功能 | 级别 | 为什么这个级别 | 验收标准 | 谁提的 |
|---|---|---|---|---|---|
| 1 | | P0 | 缺了拿不到结果 | 当……时，应…… | 用户原话 |
| 2 | | P0 | | | |
| 3 | | P1 | | | |
| 4 | | P2 | | | |

## 常被误判为 P0 的三样（通常都是 P2）

| 功能 | 为什么不是 P0 | 什么时候才需要 |
|---|---|---|
| 登录注册 | 一个/几个人用不需要账号 | 有陌生人用、要区分数据归属时 |
| 后台管理 | 内容不多时直接改数据更快 | 内容每周要改、且不是自己改时 |
| 数据统计 | 有 10 个用户之前，统计没有意义 | 有留存问题要诊断时 |

## 砍功能的标准动作

1. 把所有候选功能列出来（10–15 个）
2. 让用户砍到 3 个 → 这 3 个是 P0 候选
3. 再过一遍"删了还能拿到结果吗" → 定 P0/P1
4. 砍掉的全部记进"不做清单"，**不要偷偷做**
