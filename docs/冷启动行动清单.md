# 冷启动行动清单（P1：两周拿到 10 个真实用户反馈）

> 背景：SWOT 分析判定"零真实用户反馈"是当前最大短板之一（W3/W5）。Issue 模板已建好，缺的是第一批真实问题。本清单是可勾选的执行单，目标：**两周内拿到 10 个非本人用户的一次完整使用反馈**。

## 第一周：铺渠道（目标：内容上线 + 触达 300 人）

- [ ] **D1-D2 发两篇公众号文章**（已成稿，F 盘存档）：
  - 《AI 把我的需求挖得很清楚，然后给了我一份 PRD 就跑了》→ 文末放 v2p GitHub Release 链接
  - 《产品快做完了，我才知道它不能上线》→ 文末放 rfe GitHub Release 链接
- [ ] **D2 写第三篇**：《我这个技能是怎么连续翻车两次的》（素材：examples/06 真实失败复盘案例）——坦诚复盘文，投社区效果最好
- [ ] **D3 投放知乎/即刻/V2EX**：改写成帖子（知乎"AI 编程"话题 / 即刻"AI 探索站" / V2EX「分享创造」节点），每篇带一个真实踩坑故事 + Release 链接
- [ ] **D4 WorkBuddy 技能市场/社群**：确认技能上架状态；在 WorkBuddy 用户群发"找人内测"帖（明确说：反馈 5 分钟，Issue 模板已备好）
- [ ] **D5 朋友圈/私域**：定向找 5 个"正在做小程序/开店/做产品"的朋友，一对一邀请试用

## 第二周：收反馈（目标：10 份 + 归档）

- [ ] **每日盯 Issue**：bug反馈 / 用后感反馈 / 踩坑规则提交三个模板的动态，24 小时内回复
- [ ] **D8-D11 私聊回访**：对已下载用户发三问："卡在哪一步？哪句话没看懂？产物是不是你想要的？"
- [ ] **D12 反馈归档**：新建 `feedback/2026-Q4.md`，每条记录：来源 / 卡点 / 是否复现 / 对应改进项
- [ ] **D13 分诊**：真实缺陷 → 修复发 patch 版；文档不清 → 改 FAQ；新需求 → Roadmap
- [ ] **D14 公开致谢与更新**：CHANGELOG 记录"首批 10 位用户反馈驱动的 N 项改进"，回复所有提 Issue 的人

## 成功标准（可数）

| 指标 | 目标 | 达成判据 |
|---|---|---|
| 非本人完整使用 | ≥10 次 | 每次有 Issue 或私聊记录 |
| 真实缺陷发现 | ≥3 个 | 可复现、已修复或已排期 |
| 内容曝光 | ≥300 阅读 | 公众号/社区后台数据 |
| 踩坑规则众筹 | ≥1 条 | 「踩坑规则提交」模板收到第一条 |

## 提醒

- 反馈比下载重要：10 个深聊 > 1000 个下载；
- 每条真实反馈在 CHANGELOG 里公开致谢（用户愿意留名的话）——这是冷启动阶段唯一买不到的资产；
- 不要刷量：真实的小数字比虚胖的大数字更有决策价值（呼应 SWOT 结论"真实用户的一百次使用，价值大于作者自测一千次"）。
