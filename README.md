# 模糊需求挖掘与产出生成器（Vague to Product）

> **你给一句模糊的话，我还一个能用的东西。**
> 不限于软件——文档、表格、图形、3D 模型、音视频、资料库、实物方案，同一套挖掘逻辑。

很多人不是没想法，是想法没成形。这个工具不问你"要什么功能"，而是**给你选项让你判断**，然后**按需求的真实分量决定挖多深**，最后直接产出成品。

---

## 它解决什么

| 你的状态 | 它会做什么 |
|---|---|
| "我想做个 App" | 先判形态：真需要 App，还是一个小程序/网页就够（差 5 倍成本） |
| "我有个想法，但说不清" | 给选项让你挑，挑完就清楚了 |
| "功能想了一堆，不知道先做哪个" | 让你砍掉 7 个，留 3 个 |
| "做出来总不是我要的" | 每轮回读确认，错在第二轮就纠，不在交付时才发现 |
| "不知道从哪开始" | 2 小时内给你一个能点开的东西 |
| **"这事挺复杂，怕想漏"** | **自动上调深度，分批深挖，每批出阶段产出让你验收** |

---

## 关键差异：深度不是固定的

这是 2.0 的核心。**同一个工具，对不同需求用不同深度。**

| 需求 | 判定深度 | 问几轮 |
|---|---|---|
| "帮我起个文件名" | D0 直达 | 0 轮，直接做 |
| "写一页纸的会议通知" | D1 标准 | 2 轮 |
| "给客户写一份服务方案" | D2 深挖 | 3–5 轮 |
| "要做个涉及收款和分账的平台" | D3 深度 | 5–8 轮 |
| "我有个想法但完全没想清，要卖给别人" | D4 分层 | 8 轮以上，分 3 批 |

深度由 **五个信号** 打分得出（0–10 分）：

```
影响半径   只影响自己 ──→ 影响公众/涉钱/涉法
不可逆性   改起来便宜 ──→ 已发布/已投产/已开模
未知量     很清楚     ──→ 只有感觉
复杂度     单一静态   ──→ 交互系统/多角色
复用性     一次性     ──→ 要给别用/要卖/要维护
```

**为什么这件事重要**：问少了会返工，问多了会被嫌烦。固定三轮两头不讨好。

---

## 八类产出形态，问的不是同一批问题

| 形态 | 必挖 | 典型问题 |
|---|---|---|
| 软件应用 | 对象·质量·边界 | 它最核心的**那一个**动作是什么？ |
| 文档报告 | 对象·质量·边界 | 读者读完要做什么**决定**？ |
| 表格数据 | 对象·质量·约束 | 这张表**一行代表什么**？ |
| 图形图像 | 对象·质量·交付 | 用在哪、**多大尺寸**？ |
| 3D 模型 | 对象·质量·交付 | 拿去**干什么**（看/渲染/打印/开模）？ |
| 音视频 | 对象·质量·边界 | 在**哪放**、多长？ |
| 资料知识 | 对象·边界·演化 | 以后**谁维护**？ |
| 实物服务 | 对象·约束·质量 | **数量级**多少？ |

> 把"软件的问法"套到文档上，会问出没法用的答案。所以第一步永远是判形态。

## 一条命令联合推演（v2.2.0 编排层）

```bash
v2p plan -t "我要做一个招聘小程序"
```

这一条命令会：判定形态与深度 → 给出第一轮 4 个追问 → **静默调用 fuzzy-reverse-flow** 召回合规红线、资源底线、历史坑预警 → 生成倒排里程碑骨架 → 输出统一报告 + 含「合规闸门」的核查卡。你不需要知道 rfe 的存在；想单独做可行性评估时，仍可直接 `rfe recall -q "招聘"`（两套工具独立可用，只是多了一条联合路径）。

交付收尾是强制的：`v2p settle pitfall/rule`（先入待审区，`rfe pitfall approve` 转正）→ `v2p settle done`。没沉淀过任何经验就标记交付，`v2p spec check` 会拦下你。需求变了：`v2p change -t "改了什么"`，自动重跑红线 diff 与工期推演。

其他：`v2p use 项目名`（口味档案按项目隔离）、`v2p gate manual`（手测清单+截图留痕校验）、`v2p bundle --items app,doc,sheet`（多产物一致性对账）、`v2p viz depth/-gates`（SVG 可视化）。

> 免责：规则与检查项为经验总结，不构成法律意见；自动化检查不能替代人工测试。

## 用起来

### 对话中

> 我想做个帮老人找零工的 App

它会先说：形态判定、深度初判、三处歧义 + 默认假设，然后一次问 4 个带选项的问题。

### 命令行

```bash
v2p route -t "我想做一份给投资人的商业计划书"   # 判形态 + 算深度 + 给第一轮问题
v2p depth --impact 2 --reversi 0 --unknown 1 --complex 0 --reuse 1
v2p ask --form doc --depth D2 --round 2 --done goal,scene
v2p forms                                    # 看八类形态与必挖点
v2p spec new --title "XX" --brief            # 通用产出定型卡（非软件）
v2p spec check --file XX.md                  # 能不能交付
v2p profile depth D2                         # 记住深度习惯

# 交付质量闸门
v2p gate card -f app -d D2 -o 核查卡.md       # 生成填空式核查卡
v2p gate list -f doc                         # 文档只出 12 项
v2p gate redteam -f app                      # 12 步破坏性测试
v2p gate scan -p ./项目                       # 静态筛查（筛子，非判据）
```

`v2p route` 实际输出：

```
【形态判定】文档与报告（doc）　置信：高　命中：计划书、商业计划
【初判深度】D2 深挖（4/10）
  影响半径 ██ 2　影响公众 / 涉及钱 / 涉及法律
  复杂度   ·· 0　单一静态产出
【轮次预算】3–5 轮，每轮 ≤4 题
【覆盖预演】必挖的 3 个维度中覆盖 3 个　✓
【第一轮先问这 4 个】…
```

## 三个设计要点

**1. 只问能被判断的问题**
"你觉得这个设计好吗"——用户答不出。"这两版你选哪个"——他立刻能答。所以每题都是选项，不是填空。

**2. 每题都标代价**
选项后面写"要 3 天""要资质""省掉登录"，让选择基于真实成本，而不是感觉。

**3. 必须产出"不做什么"**
只说要做什么的规格是废纸。软件的 P0 超过 5 个、非软件的"不做什么"为空，`spec check` 会直接拦下。

---

## spec check 检查什么

两套标准，自动识别：

```bash
$ v2p spec check --file prd.md            # 软件 PRD
[错误]
  ✗ P0 有 7 个，超过上限 5 个——说明没有 MVP
  ✗ 「不做清单」是空的或只有占位

$ v2p spec check --file brief.md --form doc   # 非软件定型卡
[错误]
  ✗ 「必须包含的内容」太短——没有内容清单，产出必然缺项
  ✗ 「不做什么」是空的
[提醒]
  ! 没看到「当……应……」格式的验收标准
```

**软件看 P0 数量，非软件看内容清单**——用错标准会得到假验收。

## 交付质量闸门（治"看着像 AI 做的"）

需求挖对了、东西也做出来了，还是一眼看出业余——问题几乎总在同一处：**只覆盖了正常路径，剩下的空态、错态、边界、并发、权限全在裸奔。**

所以闸门是**两段式**，不是交付后的清单：

**第一段：动手前先填状态矩阵**

| 情况 | 用户看到什么 |
|---|---|
| 加载中 / 没有数据 / 出错 / 成功 / 不可用 / 极端量 / 素材缺失 | 七行各写一句具体的话 |

填不出来的那一行，就是还没挖到的需求——回阶段二补，不许"到时候再说"。

**第二段：交付前过六道闸门**

| 闸门 | 治什么病 | 项数（软件） |
|---|---|---|
| 完整态 | 点了没反应、列表空白、报 undefined、保存没提示 | 13 |
| 交互 | 浮层被遮、背景乱滚、返回丢筛选、连点发三次 | 8 |
| 布局 | 手机横滚、长标题撑爆、深色看不见字 | 12 |
| 数据 | 假姓名假手机号、字段 undefined、差 8 小时、金额算错 | 12 |
| 工程 | 密钥写前端、构建失败、内存上涨、一错全白 | 11 |
| 可维护 | 调不存在的接口、同类两套写法、改坏回不去 | 9 |

共 65 项（软件 48 项 + 六个非软件形态的等价检查）。每项都写清 **问什么 / 怎么验 / 怎么修**。

**按形态裁剪**：文档不会被问"加载态"，3D 不会被问"滚动穿透"。
**按深度裁剪**：D0/D1 只查核心 7 项，D2 查全部阻断项，D3+ 全量。一张通知不会被 48 项吓退。

**通过标准是可数的**：

```
阻断项未通过 = 0
提醒项未通过 ≤ 3，且每条写清为什么不修
```

**静态扫描只是筛子**，不是判据：

```bash
$ v2p gate scan -p ./我的项目
阻断（2）：  [QGS-01] 疑似密钥明文 / [QGS-02] 疑似写死的假数据
阻断（1）：  列表渲染了，但没有任何空态/加载态处理
提醒（3）：  z-index 9999 / 字符串解析日期 / 调试输出残留
结论：未通过（阻断 3 / 提醒 3）
```

它扫不出运行时才出现的竞态、内存泄漏、层级冲突，也接受误报。**判据永远是 `redteam` 那 12 步真的点一遍。**
