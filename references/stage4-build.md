# 阶段四 · 直接产出

> 目的：交付**能用的东西**，不是又一次讨论。用户拿到能点、能跑、能看的东西，才会说出真话。
>
> **先按形态选产线**，再谈细节。八类形态的产出方式完全不同，别用软件的做法去交文档。

---

## 1. 形态路由（先看这张）

| 形态 | 产出什么 | 用什么做 | 交付判定 |
|---|---|---|---|
| **软件应用** | 能点/能跑的应用 | `mini-program-development`（小程序）/ `sites`+HTML（网页）/ `cloud-service`（要存数据登录）/ 本地脚本（批处理） | 能打开、主流程 3 步走通 |
| **文档报告** | Word / PDF / PPT | `workbuddy-docx` | 读者能据此做决定 |
| **表格数据** | xlsx / csv | `workbuddy-sheet-generation` / `workbuddy-sheetagent` | 输入能算出对的结果 |
| **图形图像** | PNG / SVG / 可编辑源文件 | `ImageGen` / `show_widget`（图表与示意图）/ HTML+CSS（界面） | 在目标尺寸下看得清、信息层级对 |
| **3D 模型** | STL / OBJ / STEP / 渲染图 | `buddy-multimodal-generation`（文生 3D）/ 脚本生成 STL / 参数化建模 | 目标软件能打开、无破面 |
| **音视频** | MP4 / 脚本 / 分镜 | `VideoGen` / 分镜脚本文档 | 能直接发，或能直接拿去生成 |
| **资料知识** | 目录 + 文件体系 / 知识库 / 网页 | `library` 技能 / 本地目录结构 / 单页检索页 | 拿一个真问题，3 秒找到 |
| **实物服务** | BOM + 图纸 / 方案 / SOP | 不出代码，出清单与图纸 | 能直接询价或直接执行 |

### 软件内部再分流

```
需要装到手机桌面？
├─ 不需要 → 网页/H5（最快，能发链接）
└─ 需要
   ├─ 只在微信里用 → 微信小程序
   ├─ 要上应用商店 → 原生 App（成本 ×5，先确认真的需要）
   └─ 内部员工用 → 小程序 + 企业微信，或直接网页

要不要存数据 / 多人用 / 登录？
├─ 不要（单机、单人） → 单文件 HTML / 本地脚本，零后端
└─ 要 → 云服务（数据库 + 登录 + 存储）
```

## 2. 各形态起手模板

### 2.1 单文件 HTML（最快，先做这个）

适用：一人或几人用、要能点、要能演示。

```
一个 .html 文件，内嵌 CSS/JS，数据存 localStorage
必须包含：
- 空状态（没数据时说什么、给什么按钮）
- 加载态（点了之后 300ms 内必须有反应）
- 错误态（失败时说人话 + 一个重试）
- 成功态（保存后怎么知道成了）
- 禁用态（条件不满足时按钮变灰并说明原因）
- 主操作按钮（只有 1 个，就一个）
- 列表 / 卡片（能看、能删）
- 移动端适配（viewport + 大按钮）
```

> 七态写法与判据 → `quality-gates.md` 第 3 节；核查卡 → `v2p gate card -f app -d D2`

**为什么先做这个**：2 小时能出，用户点一下就知道对不对。改 10 次也不心疼。
确定要了，再升级成小程序。

### 2.2 微信小程序

适用：要给一批人用、要转发、要长期运营。

必做：
- 首页（一屏能看到核心价值）
- 主流程 3 步内走通
- 空/错/加载三态
- 适老化（若用户偏大：字号 ≥32rpx、主按钮高 ≥88rpx、不用滑动手势）

### 2.3 文档

适用：要说服别人（客户/投资人/领导），不是自己用。

必须有的顺序：结论 → 证据 → 方案 → 风险 → 下一步。
（问题红字、答案蓝字是这位用户的个人习惯，默认遵守。）

**文档的四条硬规则**：
1. 第一屏就要给结论（读者不会翻到第 3 页才看到答案）
2. 每个数字带来源，查不到来源的写"待核实"而不是估一个
3. 篇幅服从用途：1 页能说完的不写 5 页
4. 禁写清单贴在桌面：未核实数字 / 内部成本 / 点名 / 承诺性表述

### 2.4 表格

适用：要算、要对、要长期维护的数据。

起手四件事，缺一件就返工：
1. **一行代表什么**（写进第一行注释）
2. **每列的口径**（金额是否含税、日期是发生还是入账）
3. **谁填、必填与否**（数据校验放这一层）
4. **一个能对上的总数**（拿它验证全表没错）

> 先做 10 行假数据跑通公式，再灌真数据。反过来会改到崩溃。

### 2.5 图形

适用：要给人看、要贴在某个位置的东西。

起手顺序不能反：**用途 → 尺寸 → 信息层级 → 风格**。

1. 用途与尺寸先定（9:16 / 16:9 / A3 / 1:1）
2. 信息分三层：一眼看到 / 细看发现 / 需要时才看
3. 风格从参考图取，不自己发明
4. 字要么够大，要么删掉——小字等于没有

**自检口诀**：眯眼看，还能看出主标题吗？看不出就是层级错了。

### 2.6 3D 模型

适用：要打印、要渲染、要进引擎、要开模。

起手先定用途，因为它决定拓扑：

| 用途 | 硬要求 |
|---|---|
| 3D 打印 | 封闭实体、无破面、壁厚 ≥1.2mm、单位毫米、尺寸与实际一致 |
| 渲染出图 | 法线正确、材质分层、UV 合理 |
| 游戏引擎 | 低面数、UV 展开、命名规范、轴向正确（Y-up / Z-up） |
| 开模 | 拔模角、壁厚均匀、公差标注、STEP 格式 |

**交付时必须同时给**：模型文件 + 预览图 + 单位与尺寸说明。
不给单位是 3D 交付最常见的低级错误——打印出来差 10 倍。

### 2.7 音视频

适用：要发出去、要给人看、要讲一件事。

起手顺序：**平台 → 时长 → 钩子 → 结构**。

1. 平台决定画幅与节奏（竖屏 3 秒定生死，横屏能慢热）
2. 时长决定结构（30 秒只能一个点，3 分钟才能有转折）
3. 前 3 秒必须给一个"为什么继续看"的理由
4. 结尾给一个明确动作（关注 / 咨询 / 扫码 / 记住一句）

**交付两条路**：能给成片就给成片；不能就给"分镜脚本 + 提示词"，让用户自己生成。

### 2.8 资料与知识

适用：要沉淀、要查、要教别人。

起手先定**检索方式**，不是先分类：

1. 用户会怎么找？（记得主题 / 记得时间 / 记得是谁的 / 记得问题）
2. 按检索方式建目录，而不是按"看起来整齐"建
3. 命名规范定死（日期_主题_版本），否则三个月后没人认得出
4. 定维护人。**没有维护人的知识库，六个月内一定烂掉**

### 2.9 实物与服务

适用：要落地、要采购、要执行。

不出代码，出**四张纸**：

1. BOM（物料/规格/数量/单价/供应商）
2. 图纸或场地平面图（标注关键尺寸）
3. 时间表（谁在哪天交什么）
4. 验收单（逐项可勾选，不合格怎么处理）

**数量级决定工艺路线**：1 件走手板/3D 打印，100 件走小批量工艺，1000 件以上才值得开模。
不问数量就报价，等于瞎报。

## 3. 交付闸门（详见 `quality-gates.md`）

### 动手前：状态矩阵先填满

软件七行（加载 / 空 / 错 / 成功 / 不可用 / 极端量 / 素材缺失），非软件四行（完整 / 缺项 / 超量 / 异常）。
**填不出来的那一行就是没挖到的需求**，回去补问。

### 交付前：六道闸门

| 闸门 | 一句话判据 |
|---|---|
| 完整态 | 空、错、加载、成功、禁用，五样都有具体文案 |
| 交互 | 弹窗不被遮、背景不乱滚、返回不丢状态、连点不重复 |
| 布局 | 375 宽不横滚、长文本不撑爆、深色能看清 |
| 数据 | 无假数据、字段一致、时区正确、金额用整数分 |
| 工程 | 无密钥明文、能构建、无请求风暴、有错误兜底 |
| 可维护 | 接口真实存在、同类同写法、改完主流程回归过 |

**通过标准**：阻断项未通过 = 0；提醒项未通过 ≤ 3 且写明不修理由。

### 通用四条（所有形态都要过）

- [ ] 能直接打开/查看，不需要额外步骤或解释
- [ ] 用户拿到后，第一件事知道干什么
- [ ] 交付话术里说清了"我没做什么"
- [ ] 没答的问题都以"默认假设"形式写出来了，没有藏着

```bash
v2p gate card -f app -d D2 -o 核查卡.md   # 生成填空卡
v2p gate redteam -f app                   # 12 步照着点
v2p gate scan -p ./项目                    # 静态筛查（筛子，不是判据）
```

### 按形态追加

| 形态 | 追加检查 |
|---|---|
| 软件 | 主流程 3 步内走通、空/错状态有交代、手机可点、表单 ≤5 字段 |
| 文档 | 第一屏有结论、数字有来源、篇幅与用途匹配、无承诺性表述 |
| 表格 | 一行定义写清、口径统一、有一个可对的总数、公式无硬编码行号 |
| 图形 | 目标尺寸下眯眼能看清主标题、信息分三层、无侵权素材 |
| 3D | 目标软件能打开、无破面、单位与尺寸正确、附预览图 |
| 音视频 | 前 3 秒有钩子、字幕准确、结尾有动作、无未授权音乐 |
| 资料 | 拿一个真问题能 3 秒检索到、命名规范统一、维护人已定 |
| 实物 | BOM 可询价、图纸有关键尺寸、验收单可勾选、数量级已确认 |

## 4. 交付话术

不要只丢文件，要说清三件事：

> **这是什么**：一句话说明它解决什么
> **怎么用**：第一步点什么（只要第一步）
> **我没做什么**：明确说出砍掉的部分，避免他以为漏了

例：
> 这是给园区老人找零工的小程序首页原型，能看岗位、能拨电话。
> 打开就能看到列表，点卡片出电话。
> 我没有做：注册登录、在线支付、简历上传——这三个是 P2，等你确认有人用了再加。

## 5. 迭代节奏

**第一版永远做"最便宜的可判断版本"**，不同形态的便宜版本不同：

| 形态 | 第一版做什么 | 时长 | 为什么 |
|---|---|---|---|
| 软件 | 单文件 HTML，能点 | 1–2 小时 | 点一下就知道对不对，改 10 次不心疼 |
| 文档 | 只写"结论 + 目录"，不写正文 | 1 小时 | 结构错了，正文全废 |
| 表格 | 10 行假数据 + 全部公式 | 1–2 小时 | 公式跑通再灌真数据 |
| 图形 | 1 张草图/低精度版定方向 | 30 分钟 | 方向错了，精修全废 |
| 3D | 白模，只对形状与尺寸 | 1–2 小时 | 拓扑错了，贴图全废 |
| 音视频 | 文字分镜，不出片 | 1 小时 | 结构错了，剪辑全废 |
| 资料 | 只搭目录 + 放 3 个样例 | 1 小时 | 分类错了，搬文件最累 |
| 实物 | 手板/打样，不做批量 | 3–7 天 | 样品错了，模具全废 |

之后每一轮：**只改他明确指出的问题，不顺手重构**。他说的"这里不对"，往往只指一处。

| 轮次 | 做什么 |
|---|---|
| 第 1 轮 | 最便宜的可判断版本 |
| 第 2 轮 | 按反馈改 1–2 处（只改他说的） |
| 第 3 轮 | 升级质量（软件上后端 / 文档补正文 / 图形精修 / 3D 上材质） |
| 第 4 轮 | 补 P1 或次要内容 |
