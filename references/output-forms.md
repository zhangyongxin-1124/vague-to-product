# 产出形态矩阵（Output Forms）

> **同一句「我想做个东西」，要的可能是小程序、一份报告、一张表、一个 3D 模型。**
> 形态不同，问的完全不是同一批问题。把软件类的问法套到文档上，问出来的答案没法用。

---

## 0. 八类形态 + 一类「未定」

| 键 | 形态 | 覆盖 | 常规深度 | 必挖维度 | 最常见错配 |
|---|---|---|---|---|---|
| `app` | 软件应用 | 小程序 / 网页 / H5 / 桌面工具 / App / 游戏 / 插件 / 脚本 | D4 | 对象·质量·边界 | 说 App，实际只要一个能打开的单页；差 5 倍成本与 1 个月备案 |
| `doc` | 文档与报告 | 报告 / 方案 / BP / 合同 / 说明书 / 手册 / 白皮书 / 公文 | D2 | 对象·质量·边界 | 把文档当软件做 PRD，列一堆 P0——文档的验收标准是「读者能据此做决定」 |
| `sheet` | 表格与数据 | 台账 / 报表 / 预算模型 / 对比矩阵 / 数据清洗 | D2 | 对象·质量·约束 | 先画表头再想用途，一行代表什么没定，每个公式都返工 |
| `visual` | 图形与图像 | 图表 / 信息图 / 海报 / 插画 / LOGO / 封面 / UI | D2 | 对象·质量·交付 | 只说「好看点」，不给尺寸与使用场景——尺寸错一次全部重做 |
| `model3d` | 3D 模型与空间 | 产品模型 / 场景 / 建筑 / 打印件 / 游戏资产 | D2 | 对象·质量·交付 | 不问「拿去干什么」就开做：打印要封闭实体，游戏要低面数，两者不通用 |
| `media` | 音视频 | 短视频 / 漫剧 / 动画 / 宣传片 / 播客 / 直播脚本 | D2 | 对象·质量·边界 | 先定「要 3 分钟」再做内容——平台与用途决定时长，反过来白做 |
| `material` | 资料与知识 | 资料汇编 / 知识库 / 课程 / 素材库 / 档案整理 | D2 | 对象·边界·演化 | 只做分类不做检索，不解决「3 秒找到」，整理完还是没人用 |
| `physical` | 实物与服务 | 硬件 / 包装 / 打样 / 模具 / 场地活动 / 服务 SOP | D3 | 对象·约束·质量 | 不问数量级就报价——1 件打样和 1000 件量产，工艺路线完全不同 |
| `unknown` | 未定形态 | 只有感觉，还没说要什么 | D2 | 对象 | 急着归类。形态错了，后面全在错方向上深挖 |

> 「常规深度」不是上限，是**基准线**。信号足够高（涉钱、涉合规、已发布）就该往上走，
> 并且要明确告诉用户「这一级比常规多花几轮，原因是 X」。

## 1. 为什么形态必须先定

因为**验收标准的形式不同**：

| 形态 | 验收标准长什么样 | 没法用的写法 |
|---|---|---|
| 软件 | 「当点 X 时，应出现 Y」 | 「功能要好用」 |
| 文档 | 「读者读完能做出 Z 决定」 | 「内容要全面」 |
| 表格 | 「输入 A 能算出 B，且与手算一致」 | 「表格要清晰」 |
| 图形 | 「放在 A 位置，3 米外能看清主标题」 | 「要好看」 |
| 3D | 「导入切片软件能直接打印，尺寸误差 <0.5mm」 | 「要像真的」 |
| 音视频 | 「前 3 秒有钩子，看完知道下一步做什么」 | 「要精彩」 |
| 资料 | 「拿一个具体问题，3 秒内检索到」 | 「要系统」 |
| 实物 | 「通过 X 认证 / 通过客户验收单」 | 「质量要好」 |

**规则**：如果写不出该形态的验收标准，说明形态还没定，回到 `unknown` 先问形态。

## 2. 形态判定的四条线索

### 线索 1：动词
- 「做/开发/搭建/上线」→ 多半是 `app`
- 「写/整理成/出一份/起草」→ `doc`
- 「算/统计/对账/汇总」→ `sheet`
- 「设计/画/出一张」→ `visual` 或 `model3d`
- 「拍/剪/生成一条」→ `media`
- 「收集/归档/建库」→ `material`
- 「打样/采购/办一场」→ `physical`

### 线索 2：交付物名词
用户说的那个名词，往往就是形态：报告、表、图、模型、视频、库、样品。

### 线索 3：使用者动作
「他拿到后干什么」比「这是什么」更准：
- 拿去点 → `app`
- 拿去念/签字 → `doc`
- 拿去填 → `sheet`
- 拿去贴/发 → `visual`
- 拿去打印/开模 → `model3d` 或 `physical`
- 拿去播 → `media`
- 拿去查 → `material`

### 线索 4：不可省的物理约束
- 「必须能扫码打开」→ app 或 H5
- 「必须 A3 打印」→ visual 或 doc
- 「必须是毫米级」→ model3d / physical
- 「必须 30 秒内看完」→ media

## 3. 混合形态怎么办

真实需求经常是混合的。**不要合并，要拆主次**：

| 混合 | 主形态 | 附属 | 处理 |
|---|---|---|---|
| 小程序 + 配套说明书 | app | doc | 先做 app，说明书由 app 的结构反推（更省） |
| 报告 + 汇报 PPT | doc | visual | 先定结论，再压成 PPT（顺序反了会重复劳动） |
| 3D 模型 + 效果图 | model3d | visual | 建模时就定好渲染角度 |
| 表格 + 图表 | sheet | visual | 表结构定了图才有意义 |
| 宣传片 + 海报 | media | visual | 共用一套视觉规范，先定规范 |
| 课程 + 资料库 | material | doc | 先定检索结构，再写内容 |

**判定规则**：问一句「如果只能先交一个，交哪个？」——先交的那个是主形态。

## 4. 各形态的挖掘重点（除通用四维外，必须多问的）

### app
- 核心动作**只有一个**（能说出两个，说明是两个产品）
- 数据存哪、谁能看到
- 谁来维护（决定要不要做后台）
- 明确不要什么（登录/支付/协作/推送/后台）

### doc
- **读者读完做什么决定**（不是「给谁看」，是「看完干什么」）
- 他最想知道的那一件事
- 篇幅与深度（1 页 / 3–5 页 / 10 页以上）
- 有没有必须遵守的模板与口径
- 哪些内容绝对不能写进去（未核实数字/内部成本/点名/承诺性表述）

### sheet
- **一行代表什么**（这一题不定，全表返工）
- 要算哪些数
- 数据怎么进表（手工/粘贴/导入/接口）
- 谁看、看什么（总数/趋势/对平/明细）

### visual
- **用在哪 + 尺寸**（一起问，分开问会得到矛盾答案）
- 风格参照（最好让他给参考图）
- 要不要可编辑（一张图 / 能改字 / 分层源文件 / 做成模板）
- 一次要几张（1 张试向 vs 成套）

### model3d
- **拿去干什么**（看/渲染/打印/引擎/开模）——决定拓扑，最先问
- 尺寸依据（有图纸 / 估 / 放进某空间）
- 精度与面数
- 要什么格式文件（决定他能不能打开）

### media
- **在哪放 + 多长**（一起定）
- 手上有哪些素材（有脚本/有素材没脚本/什么都没有）
- 什么算能交（不丢人 / 带转化 / 过审）
- 不能出现什么（真人/未授权音乐/承诺效果）

### material
- 给谁用、解决什么问题
- 资料从哪来（自己写/网上收/纸质扫描/别人给的乱文件）
- 按什么结构组织（主题/时间/项目/FAQ）
- 有没有不能公开的内容（决定要不要做两版）
- **以后谁维护、多久更新**（不定这个，建完就死）

### physical
- 最终交什么（样品/小批量/量产/活动/SOP）
- **数量级**（决定工艺路线，不问就报价等于瞎报）
- 硬约束（尺寸/场地/接口/预算/交期）
- 哪些不能碰（食品接触/儿童用品/改结构）

## 5. 判定错了的代价（为什么值得先花一轮确认形态）

| 错判 | 代价 |
|---|---|
| 文档 → 软件 | 多花 5 倍成本，还要备案，用户其实只要一份 PDF |
| 软件 → 文档 | 用户拿到 20 页纸，还是不知道长什么样 |
| 表格 → 文档 | 该算的没算，用户还得自己拉公式 |
| 3D 打印件 → 展示模型 | 模型不是封闭实体，切片软件直接报错，全部重做 |
| 展示模型 → 打印件 | 面数太低，打出来是方块 |
| 视频 → 图文 | 平台不对，发了没量 |

**所以第一条铁律是**：形态没定，不往下问。`v2p route` 若判为 `unknown`，第一轮只问形态。
