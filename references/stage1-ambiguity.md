# 阶段一 · 歧义捕捉

> 目的：在开口提问之前，先把"这句话有几种理解"列清楚。**不问不知道，问了才知道自己不知道。**

---

## 1. 歧义四象限

任何一句"我想做个 XX"，都在这四个维度上同时存在歧义。逐维过一遍，就能列出要问的靶子。

| 维度 | 歧义长什么样 | 典型问法 |
|---|---|---|
| **对象**（做什么） | "管理资料"——管理什么资料？给谁管？管到什么程度？ | 这件事的核心动作是一个词吗？ |
| **受众**（给谁） | "给老人用"——老人自己操作，还是子女代操作？ | 界面复杂度、字体、流程步骤全由这个决定 |
| **形态**（怎么承载） | "App"——小程序？原生？网页？公众号？纸质表单？ | 90% 的"App"用小程序就够了，成本差 5–10 倍 |
| **目标**（为什么） | "找零工"——找到就行，还是真的完成一次雇佣并拿到钱？ | 决定要不要做支付、评价、合同 |

---

## 2. 实体抽取：从一句话里抠出四类信息

输入："我想做个帮老人找零工的 App"

| 类型 | 抽取结果 | 抽取方法 |
|---|---|---|
| 动作（动词） | 找 | 找动词 → 这是核心流程 |
| 客体（名词） | 零工 | 找名词 → 这是数据主体 |
| 主体（谁做这个动作） | 老人（❓可能是子女） | 找"帮谁" → 这是使用者 |
| 载体 | App（❓可能是小程序） | 找交付形态词 |
| 隐含利益 | 挣到钱 / 别被骗 / 子女放心 | 问"做成了对他有什么好处" |

**抽取不到就是歧义**：原话里没出现的维度，全是要问的。

---

## 3. 常见误解对照表（按经验预判）

| 用户说 | 他多半真正想要的 | 需要确认的 |
|---|---|---|
| "我要一个 App" | 一个能被找到、能办事的入口 | 一定要装到手机桌面吗？小程序行不行 |
| "要有会员体系" | 想知道谁在用、想分层服务 | 是要收费分层，还是只要区分身份 |
| "要能分享" | 想让别人看到，形成传播 | 分享到微信？还是导出图片？ |
| "要数据统计" | 想知道"这件事在变好还是变坏" | 看哪 3 个数字就够？其余都是噪音 |
| "要后台管理" | 想自己改内容，不想每次找技术 | 只改文字图片，还是要改规则 |
| "要 AI 功能" | 想省人力 / 想要个噱头 | 省哪一步的人力？说不出就先去掉了 |
| "要好看" | 觉得现在的丑，拿不出手 | 给谁看？客户还是自己 |

## 4. 默认假设的写法（不卡壳的关键）

格式：**`假设：<取值> —— 若相反则<影响>：<要改什么>`**

例：

```
假设 1：使用者是老人本人，不是子女代操作
  若相反则影响：整个交互要重做——界面从"大字体少步骤"变成"一人管多账号"，
  还要加"代操作授权"和隐私同意，工作量 +50%

假设 2：只做"看到岗位 + 电话联系"，不做在线支付与合同
  若相反则影响：需接入支付与电子签，合规与开发各 +1 个月

假设 3：微信小程序形态，不做原生 App
  若相反则影响：需上架双端应用商店、做 App 备案、软著，成本 +3–5 万
```

**为什么要写"若相反则影响"**：用户看到代价，才知道哪个选择重要。没有代价的假设，他不会认真回。

## 5. 阶段一输出模板

```
【我听到的】
一句话复述：你想做的是一个______，让______能______。
抽出的四要素：动作=  客体=  使用者=  载体=

【三处歧义（我猜的）】
① …… 默认：…… ｜ 若相反：……
② …… 默认：…… ｜ 若相反：……
③ …… 默认：…… ｜ 若相反：……

【先问 4 个，其余按默认走】
（进入阶段二第一轮）
```

---

## 6. 什么时候不需要问

- 用户已经给了 3 个以上具体功能 + 明确受众 → 直接进阶段三定型，问边界即可
- 需求是内部小工具（自己用）→ 可以少问，直接做一个给他试，用起来再改
- 已经明确说"你决定" → 按默认假设全做完，交付时列明你替他做的 3 个决定
